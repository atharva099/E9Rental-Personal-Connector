## WhatsApp security and semantic limits

WhatsAppPolicy validates simulated IDs/mode and selected groups. WhatsAppIngestionService checks group before content inspection; store/index scopes precede decode. Duplicate protection binds tenant/account/group/message and fingerprint. This is a sound simulated boundary but does not prove official webhook signature verification, subscription handshake or raw official-envelope handling. Those production/webhook controls are derived implementation needs, not extra quoted PDF obligations. Do not add an unofficial library or assume that a public API supports the organiser's proposed groups without their confirmed access guide.

No group names, roster, participant asks, participant-indexed commitments or decisions are modeled. Summary is a list of up-to-240-character prefixes. Action/commitment detection is keyword based; no grounded task status/date extraction or conversational resolution. Restricting metadata to what is actually supplied, preserving unknowns and requiring exact supporting message IDs are mandatory for any extension.

## Distinguish PDF requirements from optional enhancements

The PDF allows any queryable database/store and CLI, web UI or API. **MySQL, React, vector search, a paid LLM, external AI calls and OCR are not explicitly required.** H2 satisfies the store-choice requirement. A deterministic system can satisfy grounded QA if the required reasoning is implemented correctly; an LLM interface alone adds no compliance. OCR may be useful if authorised PDFs are image-only, but is conditional and not automatically in scope. A snapshot freshness guard, Drive owner metadata, secure official webhook verification and an isolated live-flow verifier are derived reliability/security improvements; they are not falsely counted as verbatim PDF clauses.

The eight-hour event/code-window, in-person team logistics, organiser licence text and judging timetable cannot be satisfied retroactively by polishing an existing independent practice repo. Preserve that disclosure. No automatic push, account migration, deletion, consent request or external processing is authorized by this audit.
