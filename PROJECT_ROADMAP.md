# Personal connector roadmap

This roadmap applies only to feature/personal-connectors. It does not change Challenge requirements, acceptance totals or the original eight-hour records. Estimates below are planning ranges, not an authorized implementation run or deadline.

## Baseline and status rules

The governance baseline began at bce2c52 (Personal isolation) with pending Gmail-only changes. That documentation task inspected the prior 225-test report without rerunning suites. The subsequent authorized milestone verification reran Maven clean verify (225 tests, zero failures/errors/skips), frontend tests (14 passed), the production build and seven audit regressions on 2026-10-17. See TEST_RESULTS.md for evidence; historical baseline notes do not replace this newer run.

At the original baseline all Personal provider tests were synthetic/mocked. The later controlled Gmail milestone verified a five-thread/five-message live export, saved-export ingestion, idempotent replay, limited search and five exact Q&A citations; see the dated tracker and test evidence. Gmail OAuth completion and Google Cloud prerequisites include user-confirmed evidence. This limited sample does not verify full mailbox or general question coverage. Personal Drive is unverified and disabled; WhatsApp is simulated and disabled for Personal ingestion. Q&A remains bounded deterministic.

The current Personal product direction is Live Gmail-only: explicitly approved direct Gmail Ask/Search and selected-message viewing return bounded transient results; Personal Gmail export, snapshot ingestion, history sync, indexed Gmail search and local-index Gmail Ask are gated. Historical five-message export/index evidence and user-reported live sync observations remain in the tracker but do not describe permitted current Personal routes. Existing snapshot files and H2 Gmail rows are not deleted or migrated by this gate. P9's bounded direct live-question scope remains VERIFIED as recorded; its former local-index Gmail fallback is unavailable in Personal. Challenge/SANDBOX behavior remains separate and unchanged. No gate completion upgrades P7 or Gmail V1.

VERIFIED requires all stated acceptance gates with dated evidence; PARTIAL has implemented but unmet gates; BLOCKED has an unmet external/security prerequisite; NOT STARTED has no milestone implementation/evidence. Component verification never upgrades a blocked live milestone.

## Proposed effort and order

| Sequence | Active effort estimate | Exit / contingency |
| --- | --- | --- |
| P1 closeout and P2 readiness | 3–5 hours | Start with approved read-only credential provenance/ACL review; remediate only under separate approval. Stop real access while any security gate is open |
| P3 bounded Gmail flow | 3–5 hours | Consent waiting is external; fix verified defects before expanding mailbox volume |
| P4 Drive opt-in and bounded flow | 4–6 hours | Root/account/consent first; unsupported formats stay documented |
| P5 feasibility decision | 1–2 hours | Verify current official contract; defer unsupported access rather than substitute unofficial tools |
| P6 Q&A/dashboard completion | 5–8 hours | Bounded question acceptance set first; broader retrieval/provider work requires a new scoped estimate |
| P7 lifecycle/security closure | 4–7 hours | Can begin with synthetic fixtures while access is blocked, under a separately approved task |
| P8 regression and delivery | 3–5 hours | Protected final verification allocation; failures defer release |

Estimated Google-focused local release: 23–38 active hours after this documentation baseline, excluding provider/user waiting and any new external AI or hosting scope. If P5 is feasible, allow a provisional additional 4–8 implementation/test hours, then re-estimate against the confirmed contract. A WhatsApp-enabled release has no defensible completion date until supported access is established. These are estimates, not promises; no new clock is started.

Work serially in user-approved milestones. Record actual effort when measured, checkpoint at each task end, diagnose blockers for at most 15 measured minutes and re-estimate rather than silently expanding scope. Reserve P8 for verification, not new features. No account permission, commit, merge, push or publishing is authorized by this plan.
